# Итерация 1: Ключевые компоненты финансового планирования

**Период**: Июнь 2025  
**Статус**: ✅ Завершено  
**Результат**: Production-ready сборка 322KB

## 🎯 Цели итерации

Создать 6 ключевых компонентов, демонстрирующих **реалистичные пользовательские потоки** и **современные UX-подходы** для системы финансового планирования с акцентом на:

1. **Иерархическое планирование** с древовидной структурой
2. **Трехстороннюю сверку данных** (кошельки ↔ транзакции ↔ планы)
3. **Актуализацию расхождений** plan vs fact
4. **Воронку оценок** для планирования в условиях неопределенности
5. **Быстрые инструменты** для повседневного использования

## 🏗️ Архитектурные решения

### Технологический стек:
- **React 18** с функциональными компонентами и хуками
- **Material-UI v5** для консистентного дизайна
- **Recharts** для интерактивной визуализации данных
- **React Router v6** для навигации
- **Custom TreeView** (вместо проблемного @mui/x-tree-view)

### Паттерны проектирования:
- **Container/Presentational** компоненты
- **Mock-first development** с реалистичными данными
- **Progressive disclosure** для сложной информации
- **Color-coded status** для быстрого понимания

### 2. PlanTreeView.js - Иерархическая структура планов

**Путь**: `/plan-tree`  
**Цель**: Обеспечить визуальный контроль за структурой планов и расхождениями

#### 🌳 Древовидная структура:
```
Основной фонд (fund) [constraint]
├── Резервный фонд (savings)
├── Отпуск (goal) [constraint]
│   ├── Билеты (expense)
│   └── Проживание (expense)
└── Новый ноутбук (goal)

Ежемесячные расходы (expense) [constraint]
├── Продукты (expense)
├── Коммунальные услуги (expense)
├── Транспорт (expense)
└── Развлечения (expense)
```

#### 🏷️ Типы планов:
- **fund** (фонд) - основные накопительные планы
- **savings** (накопления) - целевые сбережения  
- **goal** (цель) - конкретные цели с таргетом
- **expense** (расход) - планы трат

#### ⚠️ Система "Over/Under":
- **Over (превышение)** - зеленые чипы, экономия средств
- **Under (недостаток)** - красные чипы, перерасход
- **Агрегация вверх** - родительские планы показывают сумму дочерних расхождений
- **Constraint планы** - отмечены специальным чипом для приоритетного контроля

#### 🎯 Аналогия с профайлерами:
Подобно "hot paths" в профайлерах кода, constraint-планы выделяются как критически важные точки контроля, а детализация скрыта до необходимости.

#### 💡 Технические решения:
- **Кастомный TreeView**: Из-за проблем с `@mui/x-tree-view` создали собственную реализацию через `List` + `Collapse`
- **Рекурсивные компоненты**: `TreeNode` рендерит себя для дочерних узлов
- **Управляемые состояния**: expanded/selected/dialogOpen через useState

### 3. TransactionManagement.js - Управление транзакциями

### 4. BalanceReconciliation.js - Трехсторонняя сверка балансов

**Путь**: `/balance-reconciliation`  
**Цель**: Контролировать сходимость трех взглядов на финансы

#### 🔄 Три столпа сверки:

1. **Инвентаризация кошельков** (230,000 ₽)
   - Основная карта: 65,000 ₽
   - Наличные: 15,000 ₽  
   - Сберегательный счет: 150,000 ₽

2. **Сумма транзакций** (228,500 ₽)
   - Доходы: +385,000 ₽
   - Расходы: -156,500 ₽
   - Привязано: 195,000 ₽ | Не привязано: 33,500 ₽

3. **Сумма балансов планов** (230,000 ₽)
   - Фактический баланс: 215,000 ₽
   - Резервированный: 15,000 ₽

#### 🚨 Статусы сходимости:
- **Идеально** (≤ 0 ₽): зеленый, все совпадает
- **Хорошо** (≤ 1,000 ₽): синий, небольшие расхождения  
- **Предупреждение** (≤ 5,000 ₽): желтый, требует внимания
- **Ошибка** (> 5,000 ₽): красный, критические проблемы

#### 📈 График истории:
LineChart показывает сходимость всех трех линий во времени с возможностью выявления трендов и проблемных периодов.

#### 🔍 Раскрываемые детали:
Каждая карточка имеет кнопку "Детали" с подробной разбивкой и возможностью drill-down анализа.

### 5. PlanActualization.js - Актуализация расхождений

**Путь**: `/plan-actualization`  
**Цель**: Процесс закрытия расхождений plan vs fact

#### 🔄 Трехэтапный мастер:

**Шаг 1: Подтверждение суммы**
- Предзаполненная сумма расхождения
- Возможность корректировки
- Валидация ввода

**Шаг 2: Выбор источника/получателя**
- **Over (экономия)**: "Куда перевести сэкономленные средства?"
- **Under (перерасход)**: "Откуда взять недостающие средства?"
- Dropdown с доступными планами и их балансами

**Шаг 3: Подтверждение операции**
- Превью виртуального перевода
- Финальное подтверждение
- Создание записи в истории

#### 📊 Статистика процесса:
```
┌─────────────────────┬─────────┐
│ Планов с расхождениями │    4    │
│ Общая экономия      │ +13,000₽│
│ Общий перерасход    │ -10,000₽│
│ Чистое расхождение  │ +3,000₽ │
└─────────────────────┴─────────┘
```

#### 📜 История актуализаций:
Таблица с аудит-трейлом всех прошлых операций:
- Дата актуализации
- План и сумма расхождения  
- Выполненное действие
- Результат (обычно "Сбалансировано")

#### 💡 Бизнес-логика:
- **Экономия**: освобождает средства для перераспределения
- **Перерасход**: требует покрытия из других планов
- **Виртуальные переводы**: фиксируют все движения для аудита

### 6. ScenarioManagement.js - Воронка оценок

**Путь**: `/scenario-management`  
**Цель**: Управление неопределенностью в планировании

#### 🎯 Три сценария для каждого плана:

```
Отпуск в Европе:
├── Пессимистичный: 5,000₽/мес → 120,000₽ за 9 мес
├── Реалистичный:   10,000₽/мес → 150,000₽ за 8 мес  
└── Оптимистичный:  15,000₽/мес → 180,000₽ за 6 мес
```

#### 📊 Активный сценарий:
Toggle buttons для переключения между режимами:
- **Пессимистичный** 📉 - для консервативного планирования
- **Реалистичный** 📊 - для базовых расчетов
- **Оптимистичный** 📈 - для амбициозных планов

#### ✏️ Редактирование оценок:
- Inline-редактирование месячных взносов
- Автоматический пересчет общей суммы и времени
- Валидация и сохранение изменений

#### 📈 Уровень уверенности:
Прогресс-бары показывают confidence level для каждого плана:
- **90%+** - зеленый (высокая уверенность)
- **60-80%** - желтый (средняя уверенность)  
- **<60%** - красный (низкая уверенность)

#### 🔄 Сужение воронки во времени:
История показывает, как диапазон оценок сужается:
```
Январь: 100,000₽ - 250,000₽ (диапазон 150k)
Февраль: 120,000₽ - 200,000₽ (диапазон 80k)  
Март: 120,000₽ - 180,000₽ (диапазон 60k)
```

#### 📊 Прогнозный график:
AreaChart с диапазонами неопределенности:
- Заливка показывает "коридор возможных значений"
- Линия - базовый (реалистичный) сценарий
- Возможность переключения между планами

## 🔧 Технические особенности

### Решение проблем с зависимостями:

#### Проблема: @mui/x-tree-view
```bash
# Множественные ошибки модулей ESM
ERROR: export 'TreeView' not found
ERROR: export 'styled' not found  
ERROR: Can't resolve '@mui/material/styles'
```

#### Решение: Кастомный TreeView
```javascript
// Замена TreeView на List + Collapse
const TreeNode = ({ planId, level = 0 }) => (
  <div>
    <ListItem sx={{ pl: level * 2 }}>
      <ListItemButton>
        {/* Контент узла */}
      </ListItemButton>
    </ListItem>
    <Collapse in={isExpanded}>
      {/* Рекурсивно дочерние узлы */}
    </Collapse>
  </div>
);
```
